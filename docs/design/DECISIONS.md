# Round 2 design decisions

Decisions and deviations from the reference prototype ([reference/strecke-prototype-v2.html](reference/strecke-prototype-v2.html)) for the Phase C rework. Project-wide decisions stay in [../DECISIONS.md](../DECISIONS.md); this file is the design log for round 2. Format: what, why.

## Brief precedence
R2-1. **The round-2 brief overrides earlier docs where they conflict.** It reverses D42 (no self-grade buttons) for the Karte only, adds the Verlauf dashboard and optional goals, and replaces the three-style comparison (D50) with one palette. Why: the owner decided these after testing round 1. The older STATION.md look (warm paper, dark boards, Overpass) is superseded by the tokens below; its principles stand.

## Product
R2-2. **Run (Runde)**: about 6 cards (setting 3–12), boundary by inactivity gap, default 20 minutes (setting 5–120). Events carry a run id; events without one fall back to the gap. Why: the owner asked for a gap rule; the id keeps "Noch eine Runde" a separate run and the gap keeps abandoned runs honest.
R2-3. **Karte rating** is the learner's own four-step answer (*Nicht gewusst* / *Teilweise* / *Gewusst* / *Sofort*) mapped to FSRS 1–4. Other exercises grade automatically (wrong → Again, right → Good; slow or helped → Hard, as since Phase B). **Easy is not inferred**: no learner data exists to show that response time improves scheduling, so the default Good stays.
R2-4. **A new word rated *Nicht gewusst* stays at stage 0** (its Karte returns). Why: a quiz on a word one has just failed to recall teaches nothing.
R2-5. **"Secure" = FSRS stability ≥ 21 days** (Anki's "mature" line). Stability rather than the ladder stage so the dashboard uses the same memory model as the scheduler. The UI says: *Sicher: du erinnerst dich voraussichtlich mindestens drei Wochen lang.*
R2-6. **Three new exercise types**: Plural (choice), Kollokation (choice), Reihenfolge (tap words in order). They never gate the ladder, so old logs replay identically and the 295 existing tests stand. Typed recall (Tippen), meaning match (Bedeutung) and listening (Hören) already existed. Sheets with `collocation` or `plural` columns unlock the new ones.
R2-7. **Distractor ambiguity guard** drops synonyms, inflections, homonyms and phrases the sheet itself contains; previously chosen wrong options rank first. Existing scheduler test fixtures were given distinct headwords and glosses (they used `Wort001`, `meaning w_c0000001`, which the guard rightly treats as one lemma). No assertion was changed.
R2-8. **Goals** are optional, off by default, and shown only when switched on: one setting, "Runden pro Woche". No daily target.
R2-9. **"Diese üben"** passes the chosen words to the composer as `focus`: they come first and no new words are added for that run.

## Interface
R2-10. **Per-word pictograms are removed from the UI (F1).** The `image_key` column stays valid in the Sheet (existing data), is ignored by the app, and the Lucide pictogram shapes are no longer bundled. Icons are used for app controls only.
R2-11. **Three fixed zones on every screen (F3)**: route and run label on top; the card in the middle; actions at the thumb. Same for Karte, choice, typed, reorder, summary and week.
R2-12. **Leaving a card is a labelled button (F2).** Swipe-up advance is removed. The only gesture is the flap: drag up to peel, or tap, Enter, Space. The run can be left through *Fertig* only.
R2-13. **Palette from the prototype's `:root`**, kept as CSS variables in one file (`app/src/styles/tokens.css`). Light and dark; no red. Contrast is checked by a test (`app/src/styles/contrast.test.ts`) at WCAG AA (4.5:1 text, 3:1 graphics).
R2-14. **Type: Barlow and Barlow Semi Condensed**, self-hosted from the `@fontsource` packages (SIL OFL 1.1), latin subset. Overpass and Atkinson Hyperlegible Next are dropped.
R2-15. **The three style layers (D50) and the dev style switcher are removed.** One look.

## Deviations from the prototype
- The prototype marks a wrong choice with a grey fill only. The app keeps that and adds a check mark on the right option, so state never rests on colour alone.
- The prototype ends with "Neu starten"; the app ends with *Bis gleich.* and offers *Neue Runde* only on the summary.
- The prototype's summary shows "Wörter sicherer" per day; the app keeps the label and computes it from the log (R2-5).
- The cloze in the prototype has three text options; the app uses the same, falling back to two when the sheet has too few similar words (ENGINE.md).

## Audio (verified 2026-10-09)
R2-16. **Two providers behind `speak(text, key)`**: the device voice (default) and ElevenLabs with the learner's own key. A third (open-source or local) can implement the same `CloudVoice` interface later (`app/src/audio/service.ts`). Why: zero setup by default, better voices as an opt-in.
R2-17. **ElevenLabs facts, from official sources** (no memory):
- Text to speech: `POST https://api.elevenlabs.io/v1/text-to-speech/{voice_id}`, header `xi-api-key`, body `text`, optional `model_id` (default `eleven_multilingual_v2`) and `language_code`, query `output_format` (for example `mp3_44100_64`). https://elevenlabs.io/docs/api-reference/text-to-speech/convert
- Voices: `GET https://api.elevenlabs.io/v2/voices` with `page_size` (max 100), fields `voice_id`, `name`, `preview_url`, `verified_languages`. https://elevenlabs.io/docs/api-reference/voices/search
- Models: `GET https://api.elevenlabs.io/v1/models` (needs a key; answered `workspace_not_found` without), fields `model_id`, `can_do_text_to_speech`, `languages`. https://elevenlabs.io/docs/api-reference/models/list The app lists them at runtime instead of hard-coding ids that may change.
- `language_code` is only sent for models documented to take it (Flash/Turbo v2.5, v3); sending it to other models returns an error.
- CORS: a preflight to the API on 2026-10-09 answered `access-control-allow-origin: *` and `access-control-allow-headers: *`, so a static page can call it directly. The docs themselves do not mention browser use; if that changes, the cloud voice fails and the device voice takes over.
- Pricing, as shown on https://elevenlabs.io/pricing/api on 2026-10-09: about $0.04 (Flash/Turbo) to $0.08 (Multilingual v2, v3) per 1,000 characters; a promotional rate on v4 until 12 Oct; plan allowances differ. The Settings text states a range and sends the learner to the page rather than hard-coding a price.
- Terms (https://elevenlabs.io/terms): users keep rights to output they generate, subject to the terms and the prohibited-use policy. The terms say nothing specific about caching output or API-key handling, so the app caches only for the account holder's own device and makes the key handling explicit.
R2-18. **Key handling.** The key lives in `localStorage` on the device under its own name, is sent only as the `xi-api-key` header to `api.elevenlabs.io`, is not part of settings, is not exported, is cleared by *Schlüssel entfernen* and by *Zurücksetzen*, and is never logged or placed in a URL or error message (tests). The production build ships a Content-Security-Policy whose `connect-src` is the app itself, the Sheet web app hosts and `api.elevenlabs.io`; `script-src` is the app only.
R2-19. **Cache and cost.** Audio is cached in Cache Storage per (provider, voice, model, text hash) with a size limit (default 50 MB, oldest first) and cleared by *Audio-Cache leeren*. A per-day character cap (default 2,000) stops generating; pre-generation is off by default. Offline or on any error the device voice speaks, silently.
R2-20. **Unlocking playback.** Fetched audio is played through one shared `<audio>` element that is started silently inside a tap (*Noch eine Runde*, *Stimme testen*), because Android Chrome only allows later playback after a gesture. To be confirmed on the phone.

## Open points for the owner
- Settings > Daten shows the source and a placeholder for the last sync: the `sheet` adapter is Phase E and was not built in round 2. Hints about thin rows are live.
- The flap gesture, haptics, audio unlock and voice quality are judged on the Android phone only.

## Round 3: the real sheet (2026-10-09)

R3-1. **The sheet is read as a published CSV link** (read-only), set in *Einstellungen › Daten*. Why: it needs no Apps Script deployment and no token, works from a static page (CORS verified 2026-10-09 against a public published sheet: `docs.google.com` 307 with `Access-Control-Allow-Origin` for the page, then `*.googleusercontent.com` with `*`), and the owner can set it up alone. Trade-off: anyone with the link can read that tab, so only the word tab is published; the private README/config tabs never are. The D31 Apps Script path (private, with answers written back) stays the plan for Phase E. Contract: [../SHEET_SCHEMA.md](../SHEET_SCHEMA.md).
R3-2. **Identity** = an id column if present, else normalised word + article (+ meaning for homonyms), hashed into a deterministic `w_` id. A fixed headword typo (≤ 2 edits, same meaning, class and article, old spelling gone) keeps the word; any other headword change is a new word and the old one is archived. Why: merging two different words would attach the wrong history, which is worse than restarting one word. Deleted rows are archived, never dropped.
R3-3. **Tolerant contract:** header aliases in German and English, any order, title rows, unknown columns kept and listed, one bad row never stops a sync, a cell that breaks a rule is left out with a note instead of failing the row; looser length limits for the learner's own rows (30 words, 320 characters). "Übersetzung" right after a meaning column is the example's translation (found on the stress fixture).
R3-4. **Scheduling across exercise types: c0** (one FSRS state per word decides when; per word × type evidence decides which; plain grades). Simulated against a, b, ladder, c and crt on a synthetic learner (indicative, not proof): b loses on load and words known; weighted grades and response-time grades add nothing measurable; c0 ties or wins on the brief's five criteria and keeps production practice at about a fifth of cards, while the round-2 ladder almost never reached production. Tables in [../ENGINE.md](../ENGINE.md). The hypothesis "(c) with weighted grades" therefore did not win as a whole; only its evidence-based half was adopted.
R3-5. **New-item policy: reviews first.** New words only fill the room due words leave in a run, capped by *new cards per run*, oldest-added first. A burst of 40 rows trickles in; there is no backlog number anywhere. Consequence seen in simulation: when the learner is behind, rows added later wait until the earlier ones are introduced.
R3-6. **Ambiguity guard for chunks:** a chunk whose blank is a whole utterance gets no choice cloze (on the real sheet *Also morgen um neun? ___* accepted another chunk as well). Typing, listening and reordering stay. The ladder's capabilities follow, so such chunks are not held at a gate they can never meet.
R3-7. **Content-driven layout:** the headword shrinks to 28 px and then wraps; long sentences, meanings and options step down in size and wrap; answer lists scroll inside the actions zone; the card scrolls inside the middle zone; the four rating steps fall back to two rows, then a list, when their labels would break. Verified by a Playwright audit (no sideways overflow, no clipped text, nothing outside its zone, no control label broken inside a word) for all 11 types at 320×600, 360×740, 390×844, 430×932, text at 100 % and 130 %, plus dark mode and the 500-row sheet; a control test proves the audit catches each failure kind. Text scaling is emulated by enlarging every font by 30 % (boxes unchanged), which is how Android Chrome's text-size setting behaves; it is still an emulation.
R3-8. **Playwright** (`@playwright/test`, dev dependency only, Apache-2.0) runs against the locally installed Chrome (`channel: 'chrome'`), so no browser is downloaded. Nothing of it ships.
R3-9. **Verlauf on real-sized logs:** a 30-day total appears once there is more history than this week; the week chart switches from one square per run to scaled bars with numbers when a day has more than 8 runs.
R3-10. **Performance on 500 rows:** exercises are generated only for words that enter a run, the "known phrase" check uses a cached set, and the thin-row hints use a column check instead of building distractors (1.8 s → well under a second for 500 rows on a laptop).
R3-11. **Distractor fixes from the real rows:** light verbs (*machen, haben, geben …*) are never offered as wrong collocation partners (*Erfahrung machen* is right too), and a distractor must share the answer's capitalisation when the gap is inside a sentence (no noun offered for a verb gap, no sentence-initial *Ehrlich* for an adjective gap). Purely semantic overlaps (*Die Anmeldung / Kündigung muss schriftlich sein*) cannot be detected by rules; they are reported to the owner, and the learner can add `wrong_1/2` to steer a row.
R3-12. **Preview deployment** in a separate public repository (`strecke-preview`, built files only, GitHub Pages from its `main` branch). The live site (`/strecke/`, deployed by the main repository's workflow on every push to `main`) is not touched and `main` is not pushed. Because both sites share one origin, the preview build uses its own storage namespace (`VITE_NS=preview`: IndexedDB `strecke-preview`, its own localStorage keys and caches) and installs as its own app ("Strecke Vorschau"); the service worker now deletes only its own older shell caches. Note: the currently live build (7 Oct) still has the old service worker that deletes every other cache on its next update; that only affects the preview's offline cache, which is rebuilt on the next visit.
